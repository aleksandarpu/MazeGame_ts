● Short answer: you don't hide the Firebase config. The apiKey in
  src/firebase_init.ts only identifies your project. It ends up in the browser
  bundle whatever you do, including if you move it into Vercel env vars. What
  protects the database is security rules, Auth, App Check and API key
  restrictions. Right now the app has no Auth and no rules files in the repo, so
  anyone who copies the config from your JS can read, overwrite or delete every
  room and presence entry.

  Here's what I'd change, most important first.

  1. Anonymous sign-in (needed for everything else)

  - In firebase_init.ts, add getAuth(app) with setPersistence(auth,
    inMemoryPersistence), then call signInAnonymously(auth) before login
    finishes.
    - The in-memory setting keeps your rule that each tab is its own player. The
      default setting would give every tab the same uid.
  - In src/presence.ts:20 (src/presence.ts#L20), replace the random clientUserId
    with auth.currentUser.uid. Security rules can then check request.auth.uid.
  - In the Firebase Console, turn on Authentication → Anonymous and add
    your-app.vercel.app under Authorized domains.

  2. Security rules (the real protection)

  Add firestore.rules and database.rules.json to the repo and deploy them with
  firebase deploy --only firestore:rules,database. As a starting point:

  - RTDB status/$uid: signed-in users can read it, but only the owner can write
    it (auth.uid === $uid). Validate that name is a short string and that state
    is online or offline.
  - gameRooms/{roomId}: a signed-in user is required. Limit the size of name,
    allow at most 6 entries in players, and let a user add or change only their
    own players[uid] entry.
    - Removing other players has to stay allowed, because startRoomCleanup and
      removePlayers do it. Rules can at least require that removals only shrink
      the map.
  - gameRooms/{roomId}/game/state: only players listed in the room can write it.
  - Deny every other path.

  Rules can't enforce the game logic itself (whose turn it is, dice values).
  They stop outsiders and vandalism, not a determined cheater inside a room.
  Stopping cheaters would need Cloud Functions, which is a much bigger change.

  3. App Check

  Register the web app with reCAPTCHA Enterprise and call
  initializeAppCheck(...) in firebase_init.ts. Watch the metrics for a few days,
  then turn on enforcement for Firestore and RTDB. After that, only requests
  from your deployed site are accepted, not scripts using your copied config.

  4. Restrict the API key

  In Google Cloud Console → APIs & Services → Credentials, open the browser key:
  - Application restriction: HTTP referrers https://your-app.vercel.app/* and
    http://localhost:5173/*.
  - API restriction: only the Firebase APIs you use (Identity Toolkit,
    Firestore, Realtime Database, Firebase Installations, App Check).

  If you're on the Blaze plan, also set a budget alert.

  5. Vercel setup

  - The framework preset is Vite: build command npm run build, output folder
    dist. Your vite.config.ts already has base: "/", which is what Vercel needs.
  - You can optionally move the config to VITE_FIREBASE_* env vars (in
    .env.local, which you'd add to .gitignore, plus Vercel project settings).
    That helps you switch between dev and prod projects, but it doesn't make the
    key secret.
  - You can optionally add a vercel.json with security headers
    (X-Content-Type-Options, Referrer-Policy, and a CSP that allows
    *.googleapis.com, *.firebaseio.com over wss:, Google Fonts and reCAPTCHA).
  - .github/workflows/deploy.yml will keep publishing to GitHub Pages. If you
    drop Pages, disable it or add the Pages domain to the referrer list.

  The key is already in git history. That's fine once steps 2–4 are done,
  because the restrictions are what matter, not keeping the key secret.

  Do you want me to implement steps 1, 2 and 5 (Auth, both rules files,
  vercel.json, env vars)? Steps 3 and 4, plus deploying the rules, have to be
  done in the Firebase and Google Cloud consoles.
